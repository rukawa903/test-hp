# 「3分マージ部屋」企画書 / 要件定義書

> スマホ向けカジュアルゲーム。マージ × 部屋づくり × カジュアル育成。
> 1セッション3分前後。**「売れること」と「Claude Codeで作りやすいこと」の両立**を最優先で設計。

- 想定プラットフォーム: スマホ（まずは縦持ち1画面）
- 想定実装: Webベース（HTML/CSS/JS）→ 後でアプリ化（Capacitor等）
- 想定開発者レベル: ゲーム開発経験が少ない人が、段階的に完成まで到達できること

---

## 1. このゲームが売れるための前提整理

### なぜこのジャンルが成立しやすいのか
- **マージ（合成）は世界共通で説明不要**。「同じものを2つくっつけると進化する」は言語を問わず1秒で理解できる。
- **短時間プレイと相性が良い**。通勤・寝る前・休憩のスキマ時間にハマる。リテンション（継続率）を取りやすい。
- **広告と課金の両方が成立する**。1回の行動が短く区切られるため、広告挿入ポイントを自然に作れる。
- **コンテンツ追加が容易**。アイテム・部屋・オーダーを足すだけで寿命が伸びる＝運用が軽い。

### どんなユーザーに刺さるのか
| セグメント | 特徴 | 刺さる要素 |
|---|---|---|
| メイン: 25〜45歳女性 | スキマ時間プレイ、片付け・模様替え・収集が好き | 部屋が綺麗になる達成感、collectible |
| サブ: カジュアルゲーマー全般 | パズル/放置/育成を回遊 | サクサク進む快感、ご褒美の頻度 |
| ライト: 普段ゲームしない層 | 操作が難しいと即離脱 | 説明不要のマージ、失敗しない設計 |

### 競合に埋もれないための設計方針
- **「マージ単体」では勝てない**（Merge Mansion等の強豪が存在）。マージは「手段」、目的は**「自分だけの部屋が育つ」**に置く。
- **テーマと世界観で刺す**（後述の差別化案）。マージは中身が似るので、**見た目・物語・対象ユーザーで差別化**する。
- **1プレイ3分の気持ちよさ**を最優先KPIにする。長時間拘束を狙わない。

### この企画で最も重要な成功要因（1つ選ぶなら）
> **「3分でちゃんと部屋が前進した」という手応えを、毎回必ず返すこと。**
> マージの操作快感 × 部屋の見た目変化 × ご褒美の頻度、この3つの“返し”が崩れると即離脱する。ここに全リソースを集中する。

## 2. コアゲーム設計

### コアゲームループ
```
[生成装置をタップ] → [アイテムが出る] → [同じものをマージして進化]
   → [オーダー（注文）の要求アイテムを納品] → [報酬（コイン/素材）]
   → [部屋パーツを解放・配置] → [部屋が綺麗になる] → 最初に戻る
```
1ループ = 約20〜40秒。1セッション = このループを5〜8回。

### 時間ごとの遊び方の変化
| 経過 | プレイヤー体験 | 設計意図 |
|---|---|---|
| 〜1分 | 生成装置を叩いてマージするだけ。すぐ1個納品できる | 即・成功体験。離脱を防ぐ |
| 〜3分 | オーダーを2〜3個こなし、部屋パーツが1つ解放される | 「前進した感」＝今日のゴール達成 |
| 〜10分 | エネルギー切れ／高レベル素材待ちで一区切り。明日また来る理由が残る | 計画的な離脱点。広告・課金接点 |

### 「また遊びたい」と感じる要素（リテンション装置）
1. **未完成の部屋**（あと少しで次の部屋が見える＝ツァイガルニク効果）
2. **デイリーボーナス**（連続ログインで価値が伸びる）
3. **エネルギー回復待ち**（時間が経つと遊べる＝再訪動機）
4. **コレクション図鑑の埋まっていない枠**
5. **期間限定オーダー**（運用フェーズ）

### 難易度の上げ方（詰まらせない）
- **要求レベルを“1段階だけ”先に置く**。今Lv4が作れるなら、オーダーはLv5を要求。
- **新アイテム系統を順番に解放**して、一度に覚えることを増やさない。
- **マージ回数は線形、報酬は逓増**にして「作業感」より「伸びる感」を出す。

### 詰まりすぎない設計（救済）
- 盤面が埋まったら**低レベル品を売却/ゴミ箱**で空ける。
- **オーダーはスキップ可能**（コインor広告）。理不尽に止めない。
- エネルギーは**広告1回で部分回復**。お金がなくても進める。

### 飽きにくい進行設計
- **部屋を「章」で区切る**（部屋1→部屋2…）。各章で新アイテム系統＋新BGM＋新背景。
- **小さな目標を常に3つ表示**（オーダー枠3つ）。1つ終わると即補充。
- 「やることがゼロの瞬間」を作らない。

## 3. 具体的なゲーム仕様

| 項目 | 初期仕様（MVP想定） | 備考 |
|---|---|---|
| 盤面サイズ | **7×7（49マス）** | 6×6だと窮屈、8×8だと重い。7×7が快適 |
| アイテム種類数（系統） | **3系統**（例: 家具素材 / 植物 / 装飾） | 1系統あたり Lv1〜Lv6 |
| マージ基本ルール | 同種・同レベルを2つ隣接でなく**ドラッグで重ねる**と1段上に進化 | 3-merge等は後回し |
| 生成装置 | **タップで一定回数アイテムを生成**（チャージ式） | 例: 装置に5チャージ、時間で回復 |
| スタミナ/エネルギー | **あり（生成装置のチャージ＝実質スタミナ）** | 別途グローバルスタミナは置かない（簡素化） |
| オーダー/ミッション | **常時3枠**。要求アイテムを納品→報酬。1枠完了で自動補充 | ミッション＝オーダーに統合 |
| 部屋の進行 | **章制**。章内のオーダーを規定数こなすと次の部屋パーツ解放 | 解放条件＝「星」の累積 |
| 部屋の解放条件 | オーダー納品で得る**★スター**を一定数貯める | お金とは別軸の進行通貨 |
| 報酬設計 | コイン（消費）／素材（生成促進）／★スター（進行） | 3通貨に絞る |
| デイリーボーナス | 7日サイクル。Day7に大きめ報酬（限定装飾など） | カレンダー型 |
| リトライ/救済 | オーダースキップ、盤面整理（売却）、広告でエネ回復 | 詰み防止 |
| 広告導線 | ①エネ回復 ②報酬2倍 ③オーダースキップ ④ガチャ無料券（運用後） | すべて「任意・報酬型」 |
| 課金候補 | ①エネルギー無限パス（時間制） ②広告除去 ③コインパック ④限定装飾パック | 後述6章 |
| 無課金で遊べる範囲 | **全部屋クリア可能**。課金は“時短と見た目”のみ。進行を金で壁にしない | 重要な信頼設計 |

### 3通貨の役割（最小構成）
- **コイン**: 装置強化・盤面整理・スキップに使う消費通貨。
- **素材**: 特定アイテムの生成確率/種を補う。オーダー報酬で入手。
- **★スター**: 部屋を進める唯一の進行通貨。**お金で大量購入させない**（達成感を守る）。

## 4. MVP設計

### MVPに必要な機能（これだけで“ゲーム”として成立する）
1. 7×7盤面 + ドラッグでマージ
2. 生成装置1種（チャージ式）
3. アイテム1〜2系統（Lv1〜5程度）
4. オーダー枠（最低1〜3枠）+ 納品 + コイン報酬
5. 部屋パーツ解放（★スター or オーダー数で2〜3段階）
6. セーブ（ローカル保存）
7. タイトル / 盤面 / 簡易リザルトの3画面

### MVPでは入れない方がよい機能
- 課金、IAPの実装（先にUIモックだけ）
- ガチャ、確率演出
- ソーシャル、ランキング、フレンド
- 複数生成装置、複雑な合成ツリー
- 凝ったアニメ・パーティクル
- 多言語対応

### まず1週間で作る版（プレイアブル最小）
- 盤面 + マージ + 生成装置 + オーダー1枠 + コイン + 部屋背景が1段階変わる
- 目標: **「3分遊んで部屋が1回変わる」を体験できる**こと。面白いか自分で判断する。

### 次の段階で追加する版
1. オーダー3枠 + ★スター進行 + 部屋3章
2. デイリーボーナス + エネルギー回復待ち
3. 報酬型広告（2倍/エネ回復/スキップ）
4. 図鑑/コレクション
5. 課金（広告除去・パス）

### なぜこの順番か
- **最初に“面白さの核”だけ検証**する（マージ→納品→部屋変化）。ここが面白くなければ何を足しても売れない。
- リテンション装置（デイリー/エネ）は**核が面白い前提**で効く。順序を逆にすると、つまらないゲームに人を呼び戻すだけになる。
- 収益化は**人が定着してから**。早すぎる広告は離脱を招く。

## 5. 画面設計

| 画面 | 何を表示 | 何を押せる | 最優先で見せるもの |
|---|---|---|---|
| タイトル | ロゴ、部屋のチラ見せ、Start | Start / 設定 | 「気持ちよさそう」な世界観の第一印象 |
| メイン盤面 | 7×7盤面、生成装置、所持コイン、オーダー枠3、部屋へ戻るボタン | アイテムドラッグ、装置タップ、納品、スキップ | **盤面と“次に納品できるオーダー”** |
| 部屋画面 | 現在の部屋の見た目、進捗バー（★/次解放まで）、解放済みパーツ | 盤面へ、パーツ配置（任意） | **部屋がどれだけ綺麗になったか＝達成感** |
| ミッション画面 | （オーダーに統合可）デイリー/実績一覧 | 受取、盤面へ | 受け取れる報酬（赤バッジ） |
| 報酬画面 | 獲得物、2倍ボタン（広告） | 受取 / 広告で2倍 | 獲得演出（ドーパミン）と2倍導線 |
| ショップ | コインパック、広告除去、パス、限定装飾 | 購入、戻る | お得感のある1つ（パス推し） |
| 設定 | BGM/SE、通知、データ復元、利用規約 | 各トグル | 音量と通知（離脱防止） |
| チュートリアル | 指マーク誘導で「装置→マージ→納品」を1周 | 指示通りのタップのみ | **最初の成功体験を強制的に体験させる** |

> 設計原則: **盤面と部屋を行き来する2画面が主舞台**。他は補助。迷子にさせない。

## 6. 収益化設計

### 相性の良い順（推奨）
1. **広告収益（最優先・最も相性良い）**
   - カジュアル × 短セッションは広告と最も相性が良い。まず広告で土台を作る。
   - 形式: **報酬型動画（リワード）中心**。インタースティシャルは控えめに。
2. **買い切り・パス型収益（次点）**
   - 「広告除去パス」「シーズンパス（30日で報酬解放）」は心理的ハードルが低く、継続課金になりやすい。
3. **課金収益（IAP・3番目）**
   - コインパック・限定装飾。**進行を金で買わせない**範囲に留める。

### 広告を出すタイミング（OK / NG）
| OK（報酬型・任意） | NG（強制・うざい） |
|---|---|
| 報酬2倍 | 起動直後の全画面 |
| エネルギー回復 | マージ1回ごとの割り込み |
| オーダースキップ | 操作を遮る位置のバナー |
| デイリー追加ガチャ | 連続2回の全画面 |
- インタースティシャルは**「部屋クリア＝区切りの良い瞬間」に1回**程度まで。

### どこまで無料にするか
- **全部屋クリア・全ゲーム進行は無料で可能**にする。
- 課金/広告は**「時短」と「見た目（装飾）」と「快適さ（広告除去）」**のみ。

### 課金の心理的ハードルを下げる方法
- 最初の課金を**¥160〜¥370の少額パック**にする（初回限定2倍）。
- **広告を見る人 → パス購入**へ自然誘導（「広告がもう面倒な人へ」）。
- 装飾は**プレビュー可視化**（着せ替え後の部屋を見せてから売る）。

### やりすぎると逆効果な点
- 進行を金で壁にする（pay-to-progress）→ 信頼喪失で即離脱・低評価。
- 広告頻度過多 → リテンション崩壊。広告は「報酬を取りに行く能動行為」に寄せる。
- ★スターを直接販売 → 達成感が消える。やらない。

## 7. 差別化案（5案以上）

| # | 軸 | 案 | 狙うユーザー | 実装難度 |
|---|---|---|---|---|
| 1 | テーマ/世界観 | **「亡き祖母の家を片付けながら思い出を蘇らせる」**。マージで家具を直すと回想が解放 | 物語好き・30〜50代 | 低（テキスト＋背景） |
| 2 | 顧客層 | **「推し（VTuber/アイドル）の配信部屋づくり」**コラボ前提のガワ | ファンダム層 | 低（差し替えで横展開可） |
| 3 | UI/見せ方 | **手描き温かみ系 or ジオラマ風ミニチュア**で“可愛い世界”に統一 | 女性・癒し需要 | 中（素材依存） |
| 4 | 報酬の見せ方 | 報酬を**「ポラロイド写真が1枚増える」**形に。図鑑が思い出アルバムになる | collectible好き | 低〜中 |
| 5 | 部屋の成長演出 | **Before/Afterスライダー**で散らかった部屋→綺麗な部屋を比較表示。SNS映え | シェア狙い | 中 |
| 6 | 収集要素 | **季節/イベントで部屋が衣替え**（春夏秋冬・ハロウィン等）。限定装飾図鑑 | 継続層 | 中（運用） |
| 7 | 物語性 | **章ごとに短い4コマ/手紙**が挟まる。読み物として弱リテンション | 読み物好き | 低 |

> 推奨: **案1（思い出の家）× 案4（ポラロイド報酬）× 案5（Before/After）**。実装が軽く、感情・SNS・収集が同時に効く。

## 8. Claude Codeで実装しやすい技術設計

### 推奨技術構成
| レイヤ | 採用 | 理由 |
|---|---|---|
| 言語/基盤 | **HTML + CSS + Vanilla JS（または軽量Phaser 3）** | 環境構築ゼロ、ブラウザで即確認、Claude Codeが書きやすい |
| 描画 | まずは**DOM + CSS Grid**で盤面（Canvas不要） | デバッグ容易、初心者向き。重くなったらPhaserへ |
| 保存 | **localStorage（JSON文字列）** | サーバー不要、即実装 |
| アプリ化 | 後で**Capacitor**でWebをラップしストア配信 | Web資産をそのまま流用 |
| 広告/課金 | アプリ化後に**AdMob / ストアIAP**（Capacitorプラグイン） | MVPでは未実装でOK |

### データ管理方法（JSON化 vs コード固定 vs 後回し）
| 対象 | 持ち方 | 理由 |
|---|---|---|
| アイテム定義（系統・レベル・見た目・売値） | **JSON** | 追加・調整が頻繁。コードを触らず増やせる |
| オーダー定義（要求アイテム・報酬） | **JSON** | バランス調整の中心。データ駆動にする |
| 部屋/章の解放条件・背景 | **JSON** | コンテンツ追加が運用の核 |
| マージ計算・盤面ロジック | **コードで固定** | 仕様が安定。むやみにデータ化しない |
| 演出・アニメ・凝った確率 | **後回し** | 面白さの核ではない |
| 多言語・サーバー同期 | **後回し** | MVP不要 |

### アイテム定義の持ち方（例）
```json
{
  "items": [
    { "id": "plant_1", "series": "plant", "level": 1, "next": "plant_2",
      "sprite": "plant_1.png", "sell": 5 },
    { "id": "plant_2", "series": "plant", "level": 2, "next": "plant_3",
      "sprite": "plant_2.png", "sell": 12 }
  ]
}
```
- `next` を持たせるだけでマージ進化が成立（`null`なら最終形）。

### セーブデータ構造（例）
```json
{
  "version": 1,
  "coins": 120,
  "stars": 8,
  "energy": { "current": 4, "max": 5, "lastRefillAt": 1750000000000 },
  "board": [ {"cell": 0, "itemId": "plant_2"}, {"cell": 5, "itemId": "plant_1"} ],
  "orders": [ {"id":"o_12","need":"plant_3","qty":1,"reward":{"coins":30,"stars":1}} ],
  "room": { "chapter": 1, "unlockedParts": ["floor","window"] },
  "daily": { "streak": 3, "lastClaim": "2026-06-25" },
  "settings": { "bgm": true, "se": true }
}
```

### 画面遷移の考え方
- **状態1変数（`currentScreen`）で管理**するシンプルなステートマシン。
- `title → tutorial → board ⇄ room`、`board → result`、各画面から`shop/settings`をオーバーレイ表示。
- ルーター不要。`showScreen(name)` で表示/非表示を切り替えるだけ。

### 拡張しやすい設計の原則
- **「ロジックはコード、コンテンツはJSON」**を徹底。
- 通貨は3つに固定（増やさない）。
- 1関数1責務（生成 / マージ判定 / 納品 / 保存）。
- セーブに `version` を持たせ、将来のマイグレーションに備える。

## 9. 企画の弱点と対策（厳しめ）

| 弱点 | リスク | 対策 |
|---|---|---|
| 類似作が多い（レッドオーシャン） | 検索で埋もれる、差別化なしでは0DL | テーマ・物語・対象層で刺す（7章）。「マージ」を売りにしない |
| 単調になりやすい | 中盤で飽き→離脱 | 章ごとに新系統/新背景/物語を挿入。常に小目標3つ |
| 収益化しすぎると離脱 | 広告過多で低評価、信頼失墜 | 報酬型広告中心、進行は無料。広告は「取りに行く」設計 |
| 素材量が必要になる | 個人開発の最大の壁 | **AI生成＋統一トンマナ**で量産。MVPは1系統6枚から。系統を増やすより色替えで水増し |
| 難易度設計が難しい | 詰まる/簡単すぎる | オーダー要求を「現状＋1段」に固定する数式で自動化。スキップ救済を常設 |
| リテンションが核依存 | 核がつまらないと全部無駄 | MVPで“3分の手応え”を最優先検証。面白くなければピボット |
| アプリ審査/配信の壁 | 初心者がストア公開で詰まる | まずWeb公開（itch.io等）で検証→Capacitorで後からストア |

> **最大の弱点は「素材量」と「単調さ」**。この2つに対策を集中する。素材はAI＋色替えで圧縮、単調さは章演出と物語で割る。

## 10. 最終提案

### 一言コンセプト
> **「3分で、散らかった思い出の部屋がひとつ綺麗になる。」**
> マージで家具を直し、部屋を蘇らせ、思い出（ポラロイド）が増えていく癒しのカジュアル育成。

### 成功しやすい理由
- 説明不要のマージ × 感情に効く「部屋＝思い出」の目的設計。
- 短セッションで広告・パス収益が成立。運用はJSON追加で軽い。
- 素材を色替え・季節替えで水増しでき、個人開発でも寿命を伸ばせる。

### 最初の1か月でやるべきこと
1. 週1: プレイアブル最小（盤面＋マージ＋オーダー1枠＋部屋1段変化）を作り、自分で3分遊ぶ。
2. 週2: オーダー3枠・★スター進行・部屋3章。友人数名にテスト。
3. 週3: デイリー・エネルギー回復待ち・図鑑。リテンション装置を入れる。
4. 週4: トンマナ統一・チュートリアル整備・Web公開（itch.io等）で初期反応を測る。

### まず作るべき最小プロトタイプ
- **7×7盤面 + ドラッグマージ + チャージ式生成装置1種 + オーダー1枠 + コイン + 部屋背景が1回変わる + localStorage保存**。
- 目的: 「面白いか」を自分の手で判断する。ここが全ての分岐点。

### 失敗しやすいポイント → 回避策
| 失敗 | 回避策 |
|---|---|
| 最初から作り込みすぎて完成しない | MVPを死守。課金/演出/多言語は後回し |
| 核がつまらないまま機能を盛る | 週1プロトで“3分の手応え”を先に検証 |
| 素材で力尽きる | 1系統6枚スタート、AI＋色替えで量産 |
| 広告を盛りすぎて低評価 | 報酬型中心、進行は無料 |
| 配信の壁で止まる | 先にWeb公開で検証、ストアは後 |

### 私（あなた）が最初に着手すべき順番
1. **アイテムJSONとマージロジック**（核）
2. **7×7盤面のUIとドラッグ操作**
3. **生成装置（チャージ）**
4. **オーダー1枠＋納品＋コイン**
5. **部屋背景が1段変わる＋localStorage保存**
6. → ここで一度自分で3分遊ぶ（面白さ判定）
7. 面白ければ拡張（章/デイリー/広告）、弱ければテーマ・報酬演出をピボット
